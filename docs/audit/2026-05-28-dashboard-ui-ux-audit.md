# AstraPost Dashboard UI/UX Audit — 2026-05-28

**Auditor:** External senior product design review (codebase-only; no live runtime access)
**Scope:** `/dashboard` and connected flows — landing → auth → onboarding → core features
**Method:** Source-of-truth code review. URLs cited reference local routes (`src/app/...`) and components (`src/components/...`).
**Access caveat:** I was unable to authenticate to a running instance. All findings are derived from reading the codebase (pages, components, schemas, i18n bundles). Live runtime issues (CWV, real network latency, real error surfaces, screen-reader walkthroughs, browser device testing) are explicitly **not evaluated** — see §16.

---

## 1. Executive Summary

AstraPost is a feature-dense X management product that has clearly outgrown its original scope: composer, AI writer, analytics, agentic posting, achievements, referrals, affiliate, multi-account teams, and admin all live behind the same dashboard shell. The IA, plan-gate plumbing, and i18n discipline are above average for an indie SaaS — particularly the hub-and-spoke nav, the typed plan-gate pattern, and the trial banner / quota integration. Visual design follows shadcn/Tailwind conventions cleanly with proper RTL handling.

**Top strength:** the AI flows are genuinely productized — streaming SSE, mode toggles, copy/regenerate, "open in composer" handoff, plan-aware character limits, and PII redaction banner. This is ahead of Hypefury on AI ergonomics.

**Top weakness:** the entry flow is **incoherent and contradicts itself**. `/login` offers X OAuth only; `/register` offers email + password. A user who follows the marketing "Get Started" CTA lands at `/login` (OAuth only), but the page links them to `/register` (form-based) — and the two paths produce different account types with no documentation of the consequence. This is the single biggest friction point and it is reproducible from the code with zero ambiguity.

**Verdict on "simple, modern, low-friction":** modern ✅, low-friction ❌ — too many stacked banners, two parallel auth systems, a six-section sidebar, and feature surfaces that have grown faster than the IA has been pruned. Achievable with the Quick Wins in §5.

## 5. Strategic Recommendations

1. **Unify the auth entry.** Pick OAuth-first or dual-path, then make it consistent across `/login`, `/register`, and every marketing CTA. The current split costs you sign-ups and creates a long tail of "I can't sign in" support tickets where the actual problem is the user is on the wrong page. (Finding #1, #37.)

2. **Replace the banner stack with a notification center.** A single top bar with `🔔 3` showing impersonation, trial, failures, token issues, changelog, announcements behind a popover. Frees ~150–250px of fold space, dramatically improves first-impression. (Findings #5, #24.)

3. **Consolidate the IA from 6 sections to 3.** Create / Grow / Account. Merge Queue + Calendar into one "Schedule" route with view tabs. Move admin-only items into a separate Admin shell. The current IA reads like a feature changelog rather than a user journey. (Findings #6, #17.)

4. **Reframe onboarding around exploration, not commitment.** Allow "skip wizard, let me explore" on step 2. Keep the checklist on the dashboard for activation pressure. Forcing a first post through the wizard turns evaluators into bouncers. (Finding #11.)

5. **Surface AI quota and capability up front.** A persistent "X of Y AI generations · Z images this month" chip in the dashboard header. Better than learning via a 402 modal. Doubles as an upsell trigger that doesn't feel like a wall. (Finding #8.)
